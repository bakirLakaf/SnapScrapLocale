# 🤖 بوت ضاري الفلاح اليومي — Railway

بوت مستقل يعمل يومياً على Railway (عبر Cron) ويقوم تلقائياً بـ:

1. **تحميل** سنابات حساب `dary_1256`
2. **دمج** الشورتس (`merged_1`, `merged_2`...) + الفيديو الطويل (`merged_all.mp4`)
3. **رفع** الاثنين على القناة `سنابات ضاري الفلاح` مع جدولة النشر
4. **حذف** كل الفيديوهات (المدمجة وغير المدمجة) بعد نجاح الرفع

> ⚙️ يعمل **مرة واحدة ثم ينطفئ** في كل تشغيل — لا يستهلك رصيداً بين التشغيلات.

---

## ⏰ التوقيت

| الحدث | بتوقيت الجزائر (UTC+1) | بـ UTC |
|-------|----------------------|--------|
| بدء العملية (Cron) | **22:00** | `0 21 * * *` |
| نشر الفيديو الطويل | **23:00 نفس اليوم** | 22:00 |
| نشر أول شورت | **08:00 اليوم التالي** | 07:00 |
| الشورتس التالية | كل **15 دقيقة** (08:15، 08:30...) | — |

> ملاحظة: يُضبط توقيت/فاصل الشورتس عبر `SHORTS_PUBLISH_HOUR_DZ` و`SHORTS_INTERVAL_MINUTES`.

- وقت **بدء العملية** يُتحكَّم به من `cronSchedule` في `railway.json` أو من لوحة Railway.
- وقت **النشر** يُتحكَّم به من المتغير `PUBLISH_HOUR_DZ` (افتراضي 23).

## 📦 خطوات النشر على Railway

### 1️⃣ تجهيز حزمة التوكنات (على جهازك المحلي)

التوكنات وملفات الأسرار غير مرفوعة إلى git (لأسباب أمنية)، لذا نحزمها يدوياً:

```bash
python railway_dari_bot/seed_tokens.py
```

ينشئ ملف `railway_dari_bot/tokens_bundle.txt`. **افتحه وانسخ كل محتواه**.

### 2️⃣ إنشاء مشروع Railway

1. ادفع الكود إلى GitHub (مجلد `railway_dari_bot/` ضمن المستودع).
2. في [Railway](https://railway.app) → **New Project** → **Deploy from GitHub repo**.
3. اختر المستودع. سيلتقط Railway ملف `railway_dari_bot/railway.json` تلقائياً.
   - إن لم يلتقطه: في **Settings → Config-as-code** اضبط المسار إلى `railway_dari_bot/railway.json`.

### 3️⃣ إضافة الـ Volume (تخزين دائم للتوكنات)

1. في الخدمة → **Variables/Settings → Volumes → New Volume**.
2. **Mount Path:** `/app/stories`
   > هذا يحفظ `stories/tokens/` بشكل دائم حتى تبقى التوكنات المحدّثة بعد كل تشغيل.

### 4️⃣ إضافة متغيرات البيئة

في **Variables** أضف:

| المتغير | القيمة | إلزامي |
|---------|--------|--------|
| `TOKENS_BUNDLE` | (الصق محتوى `tokens_bundle.txt`) | ✅ نعم |
| `SNAP_USERNAME` | `dary_1256` | افتراضي موجود |
| `CHANNEL_ID` | `UCg5d06i5nWe5FihOOilC-Kg` | افتراضي موجود |
| `INFLUENCER_NAME` | `ضاري الفلاح` | افتراضي موجود |
| `PUBLISH_HOUR_DZ` | `23` | اختياري (ساعة نشر الفيديو الطويل، نفس اليوم) |
| `SHORTS_PUBLISH_HOUR_DZ` | `8` | اختياري (ساعة أول شورت، اليوم التالي) |
| `SHORTS_INTERVAL_MINUTES` | `15` | اختياري (الفاصل بين كل شورت) |
| `DELETE_AFTER_UPLOAD` | `1` | اختياري (`0` لتعطيل الحذف) |
| `FFMPEG_THREADS` | `2` | اختياري (حد خيوط ffmpeg لتفادي نفاد الذاكرة) |
| `FORCE_RELOAD` | `0` | اختياري (`1` لإعادة تنزيل تاريخ سبق تحميله) |
| `SNAPSCRAP_USER_ID` | `1` | اختياري |

> 🔄 **إعادة معالجة يوم سابق:** `download_history.json` يسجّل ما حُمِّل لتفادي التكرار.
> لإعادة تنزيل ورفع تاريخ سبق التعامل معه (مثلاً بعد فشل)، اضبط `FORCE_RELOAD=1`
> مؤقتاً وشغّل البوت، ثم أعِده إلى `0`. **اتركه `0` للتشغيل اليومي العادي** حتى لا
> يُعاد النشر إن تكرر تشغيل اليوم نفسه.

> 🛡️ **بوابة أمان:** لا يرفع البوت ولا يحذف المصادر إلا بعد التأكد أن الدمج نجح
> وأن الفيديو سليم (عبر ffprobe). إن فشل الدمج، تبقى المصادر محفوظة لإعادة المحاولة.
>
> 🧵 **حد الذاكرة:** إن ظهر `SIGKILL 9` أثناء الدمج (نفاد ذاكرة)، قلّل `FFMPEG_THREADS`
> إلى `1`، أو ارفع ذاكرة الخدمة من إعدادات Railway.

### 5️⃣ ضبط جدولة الـ Cron

- موجود مسبقاً في `railway.json`: `"cronSchedule": "0 21 * * *"` (22:00 الجزائر).
- لتغيير الوقت لاحقاً **دون لمس الكود**: عدّل التعبير من لوحة Railway
  (**Settings → Cron Schedule**). التعبير بتوقيت **UTC**.

## 🔁 تحديث التوقيت لاحقاً

- **تغيير ساعة بدء العملية:** عدّل `cronSchedule` من لوحة Railway (UTC).
  مثال: للساعة 20:00 الجزائر → `0 19 * * *`.
- **تغيير ساعة النشر:** عدّل المتغير `PUBLISH_HOUR_DZ`.
